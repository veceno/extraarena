# Боевая система ExtraArenaRaS

## Архитектура

Двухуровневая архитектура:

```
Frontend (Telegram WebApp / webapp/)
    │
    ├── HTTP REST  ──► web/server.py (aiohttp)
    │                      │
    │                      ├── matchmaking ──► infrastructure/matchmaking.py
    │                      │                      │
    │                      │                      └── ai/bot_factory.py (боты)
    │                      │
    │                      └── battle logic ──► battle_engine.py (Адаптер)
    │                                              │
    │                                              └── core/engine.py (ArenaEnvironment)
    │                                                     │
    │                                                     ├── core/state.py
    │                                                     ├── core/actions.py
    │                                                     ├── core/effects.py
    │                                                     └── core/converter.py
    │
    └── WebSocket ──► python-socketio (реальное время)
```

- **`core/engine.py`** — чистое, детерминированное ядро движка (`ArenaEnvironment`). Не зависит от БД, сети, UI.
- **`battle_engine.py`** — адаптер: сериализует состояние в JSON, управляет таймерами, AFK-детекцией, интеграцией с БД.
- **`core/effects.py`** — реестр всех 33+ игровых механик.
- **`core/state.py`** — структуры данных (`GameState`, `PlayerState`, `CardInstance`).
- **`core/actions.py`** — три типа действий (`PlayCardAction`, `AttackAction`, `EndTurnAction`).

### Closed beta deployment policy

- In-memory matchmaking and active battle state are supported only with a single web worker (`MATCH_STATE_BACKEND=memory`, `WEB_CONCURRENCY=1`).
- Before restart or deploy, put matchmaking into maintenance/drain mode, stop accepting new searches, and wait for active PvP matches to finish or be terminated by the existing battle-finalization path.
- Multi-worker deployment requires a shared match-state backend first; do not scale the memory backend horizontally.

## Логика хода

### Точка входа

`ArenaEnvironment.step(player_id, action)` — *core/engine.py:220-321*

1. Проверка: игра не окончена (`status != ONGOING`)
2. Проверка: ход этого игрока (`current_turn_owner_id == player_id`)
3. Валидация действия (`action.validate(state)`)
4. Выполнение действия (`_handle_play_card` / `_handle_attack` / `_handle_end_turn`)
5. Чистка мёртвых юнитов (`_cleanup_dead_units`) — срабатывают Deathrattle
6. Проверка окончания игры (`_check_game_over`)
7. Запись в историю действий

### Начало матча

*battle_engine.py:118-306*

- **P1** начинает с `mana=1`, `max_mana=1`
- **P2** начинает с `mana=0`, `max_mana=0`
- Стартовая рука: 3 самых дешёвых **воина** из колоды
  - Design decision: the starting hand is the cheapest three warriors, not a random mulligan.
  - Герои из колоды исключаются
  - Зелья остаются в колоде
- Оставшаяся колода (воины + зелья) перемешивается
- Первый ход у P1

### Завершение хода

`_handle_end_turn()` — *core/engine.py:527-609*

1. Ход переходит противнику (`current_turn_owner_id = opponent.user_id`)
2. `turn_number += 1`
3. Противник получает ману:
   - `max_mana = min(10, max_mana + mana_per_turn)`
   - `mana = max_mana`
4. Все юниты противника пробуждаются (`is_ready = True`)
5. **Frozen**: замороженные юниты теряют флаг `is_frozen`, но пропускают активацию (остаются `is_ready = False`)
6. **Regen** (`regen_X`): каждый юнит восстанавливает X HP (до `max_hp`)
7. Противник тянет карту:
   - Лимит руки: **4 карты**
   - При переполнении → карта остаётся в колоде и не сгорает
   - Если колода пуста: сброс (graveyard) перемешивается и становится новой колодой
   - Карты в новой колоде сбрасывают состояние: `hp = max_hp`, `is_ready = False`, `is_frozen = False`
   - Если и колода, и сброс пусты — fatigue (карта не берётся)

## Механика маны

### Базовая

- `max_mana` растёт на `mana_per_turn` в начале каждого хода (classic: +1, blitz: +2)
- Потолок: **10 маны**
- Мана восстанавливается до `max_mana` в начале хода

### Стартовая мана

Герои с механикой `start_mana_X` получают +X маны при инициализации игры.
Применяется через `apply_start_game_effects()` — *core/engine.py:660-697*.

### Манипуляции маной

| Механика | Эффект | Файл |
|---|---|---|
| `mana_gain_X` | Восстанавливает X маны владельцу (не выше `max_mana`) | core/effects.py:434-451 |
| `mana_drain_X` | Крадёт X маны у противника и передаёт владельцу | core/effects.py:453-474 |

## Розыгрыш карт

`_handle_play_card()` — *core/engine.py:323-421*

### Общие проверки
- Индекс карты в руке валиден
- Хватает маны (`player.mana >= card.mana_cost`)
- Если карта требует цель (`requires_target(mechanics)`) — `target_id` обязателен
- Мана списывается

### Воин (WARRIOR)
1. Проверка лимита доски: максимум **5** юнитов
2. `consume_ally`: если есть — поглощает союзного юнита (его Atk/HP добавляются карте), поглощённый уходит в сброс
3. Карта вставляется на указанную позицию или в конец доски
4. **Summoning Sickness**:
   - `charge` → `is_ready = True` (может атаковать сразу)
   - Без `charge` → `is_ready = False` (спит первый ход)
5. Срабатывает **Battlecry** (`process_effects()`)

### Зелье (POTION)
1. Применяет эффект (`process_effects()`)
2. Немедленно уходит в сброс (graveyard)

## Атака и расчёт урона

`_handle_attack()` — *core/engine.py:423-525*

### Проверки перед атакой
1. Атакующий юнит существует на доске
2. `is_ready == True` (не спит)
3. `attack > 0`
4. **Проверка Taunt**: если у противника есть taunt-юниты и атакующий не имеет `bypass_taunt` — можно атаковать **только** taunt-юнитов. Атака героя при наличии taunt запрещена.

### Аура-бонус
Эффективная атака = базовая атака + сумма всех `aura_atk_X` от союзных юнитов на доске (кроме самого себя). *core/engine.py:711-783*

### Атака героя
1. Урон герою с модификаторами (щит, броня)
2. `lifesteal` лечит героя атакующего на величину урона
3. `instant_kill` и `unit_killer` **не работают** против героев

### Атака юнита
1. **Одновременный обмен ударами**: атакующий и цель наносят урон друг другу
2. Оба получают урон с модификаторами
3. `unit_killer`: если есть у атакующего и цель-юнит не защитилась щитом — HP цели = 0 (мгновенная смерть)
4. `instant_kill`: если есть у атакующего, одноразовый ваншот ещё не потрачен и цель-юнит не защитилась щитом — HP цели = 0 (мгновенная смерть)

### Модификаторы урона

`apply_damage_modifiers()` — *core/effects.py:843-897*

| Модификатор | Поведение |
|---|---|
| `shield` | Блокирует **весь** урон **однократно**. Щит снимается после блокировки |
| `armor_X` | Снижает урон на X |
| `armor_X_Y` | Снижает урон на случайное значение от X до Y |
| `permanent_shield` | Legacy/internal: блокирует весь урон всегда, в текущем каталоге карт не используется |

Порядок проверки для текущего каталога: `shield` → `armor`. Если legacy-механика `permanent_shield` вручную присутствует на юните, она всё ещё имеет приоритет над обычным щитом.

### Reflect

`reflect_X` — *core/effects.py:920-938*

Цель с `reflect_X` отражает X урона обратно атакующему (без рекурсии). Отражаемый урон также проходит через модификаторы атакующего.

### Lifesteal

`lifesteal` — *core/effects.py:963-978*

Атакующий с `lifesteal` восстанавливает HP герою-владельцу на величину нанесённого урона (после модификаторов). Лечение не превышает `max_hp`.

### Cleave

`cleave_X_Y` — *core/effects.py:613-648*

При атаке наносит X урона Y случайным вражеским юнитам (по одному, обновляя список живых целей между ударами).

### После атаки

Атакующий юнит теряет готовность: `is_ready = False`. Одна атака за ход.

## Победа и поражение

`_check_game_over()` — *core/engine.py:653-658*

- HP героя P1 ≤ 0 → `P2_WIN`
- HP героя P2 ≤ 0 → `P1_WIN`

### Сдача

`mark_surrender()` — *battle_engine.py:850-881*

Игрок помечается как `SURRENDERED`. Бой **продолжается** — за сдавшегося игрока играет бот.

### AFK-детекция

`mark_timeout()` — *battle_engine.py:809-848*

- Счётчик последовательных таймаутов для каждого игрока
- При **2+** таймаутах подряд → статус `AFK`
- Игрок заменяется ботом, бой продолжается

### Статусы замены игрока

`ReplacementStatus` enum — *core/state.py:62-66*

| Статус | Описание |
|---|---|
| `ACTIVE` | Игрок активен |
| `AFK` | Игрок пропал (2+ таймаута), заменён ботом |
| `SURRENDERED` | Игрок сдался, заменён ботом |
