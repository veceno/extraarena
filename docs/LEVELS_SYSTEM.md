# Система уровней карт

Документ описывает текущую реализацию уровней 1-10 в боевом движке.
Источник истины: `core/card_scaling.py`, применение: `core/converter.py`.

## Коротко

- Каждая карта получает уровень при создании `CardInstance` через `card_from_db()`.
- Уровни вне диапазона 1-10 считаются некорректными и сбрасываются к 1.
- Уровень 1 оставляет карту в базовом виде.
- Воины получают экспоненциальный рост атаки и HP по редкости.
- Зелья почти не имеют статов, поэтому растут только отдельные числовые механики.
- Герои получают +2 HP за уровень и ограниченный рост некоторых пассивных механик.

## Общий пайплайн

1. `core.converter.card_from_db(card_data, level)` читает базовые поля карты.
2. Механики из JSON нормализуются в список строк.
3. Диапазонные механики вида `aura_atk_1_3`, `damage_1_5`, `start_mana_1_5` приводятся к минимальному значению диапазона, если для них нет специального исключения.
4. `core.card_scaling.scale_card_by_level(card, level)` меняет статы, стоимость маны и числовые механики.
5. Уже масштабированная карта попадает в бой.

Важно: диапазон в механике сейчас не означает случайный разброс и не означает рост до верхней границы. Например, `damage_1_5` превращается в `damage_1`, а затем прокачивается по правилам зелья.

## Рост по редкости

Для воинов используется множитель:

```text
final_stat = ceil(base_stat * (1 + rarity_growth) ^ (level - 1))
```

Таблица `rarity_growth`:

| Редкость | Рост |
|---|---:|
| common | 10% |
| rare | 10% |
| start | 10% |
| superrare | 10% |
| epic | 10% |
| legendary | 10% |
| mythic | 10% |
| limited | 10% |
| divine | 10% |
| unique | 10% |
| неизвестная | 10% |

## Воины

### Базовые статы

У всех воинов растут `attack`, `hp` и `max_hp` по формуле редкости. Стоимость маны не меняется.

Примеры:

| Карта | L1 | L4 | L7 | L10 |
|---|---:|---:|---:|---:|
| Тока Киришима, common 2/1 | 2/1 | 3/2 | 4/2 | 5/3 |
| Геральт, legendary 4/5 | 4/5 | 6/7 | 8/9 | 10/12 |
| Сайтама, divine 10/10 | 10/10 | 14/14 | 18/18 | 24/24 |

### Механики воинов

Числовые механики воинов усиливаются только если попадают под один из паттернов:

| Паттерн | Формула |
|---|---|
| Любая строка с `aoe_damage_X`, включая `deathrattle_aoe_damage_X` | `X + floor((level - 1) / 2)` |
| Любая строка с `heal_target_X` или `damage_X` | `X + floor((level - 1) / 2)` |
| `battlecry_buff_X_Y`, `buff_all_X_Y` | оба числа получают `+floor((level - 1) / 2)` |
| `regen_X`, `armor_X`, `aura_atk_X`, `reflect_X` | `X + floor((level - 1) / 3)` |

Текущие карты, у которых механика реально усиливается:

| Карта | База | L4 | L7 | L10 |
|---|---|---|---|---|
| Тока Киришима | `battlecry_damage_1` | `battlecry_damage_2` | `battlecry_damage_4` | `battlecry_damage_5` |
| П.Е.К.К.А. | `armor_1` | `armor_2` | `armor_3` | `armor_4` |
| Крипер | `deathrattle_aoe_damage_2` | `deathrattle_aoe_damage_3` | `deathrattle_aoe_damage_5` | `deathrattle_aoe_damage_6` |
| Фрирен | `battlecry_heal_target_5` | `battlecry_heal_target_6` | `battlecry_heal_target_8` | `battlecry_heal_target_9` |
| Юни | `battlecry_heal_target_3` | `battlecry_heal_target_4` | `battlecry_heal_target_6` | `battlecry_heal_target_7` |

Механики, которые у текущих воинов не меняются как строка механики и усиливаются только косвенно через статы:

- `taunt`
- `shield`
- `bypass_taunt`
- `battlecry_freeze`
- `consume_ally`
- `choose_shield_damage`
- `aoe_freeze`
- `desk_freeze`
- `cleave_1_2`
- `instant_kill`
- `unit_killer`
- `charge`
- `lifesteal`

Особый случай: Мидория с `cast_random_spell`. Строка механики не меняется, но эффект внутри `core/effects.py` читает `card.level`:

- случайный урон: `4 + (level - 1)`;
- лечение героя: `5 + (level - 1)`;
- заморозка: 1 цель до L4, 2 цели с L5;
- self-buff: `2 + floor((level - 1) / 2)`.

## Зелья

Зелья не получают экспоненциальный рост статов, потому что у текущих зелий `attack = 0` и `hp = 0`.

Числовой урон растёт только для механик, которые совпадают с паттерном:

```text
(spell_|battlecry_)?(aoe_)?damage_X
```

Формула:

```text
damage = X + floor((level - 1) / 3)
```

Если у зелья есть `delete_target`, дополнительно снижается стоимость маны:

```text
mana_cost = max(4, base_mana_cost - (level - 1))
```

### Текущие зелья

| Зелье | База | L4 | L7 | L10 | Комментарий |
|---|---|---|---|---|---|
| Глитч-Удар | `damage_1`, 1 мана | `damage_2` | `damage_3` | `damage_4` | `damage_1_5` сначала нормализуется в `damage_1` |
| Импульс Бездны | `aoe_damage_2`, 4 маны | `aoe_damage_3` | `aoe_damage_4` | `aoe_damage_5` | `aoe_damage_2` нормализуется из диапазона и прокачивается по правилам зелья |
| Заморозка | `freeze`, 2 маны | без изменений | без изменений | без изменений | проблемная область |
| Кража Маны | `mana_drain_2`, 3 маны | без изменений | без изменений | без изменений | проблемная область |
| Черная Дыра | `delete_target`, 5 маны | 4 маны | 4 маны | 4 маны | эффект не растёт, но стоимость падает до минимума |

## Герои

### HP

Все герои получают:

```text
hp = base_hp + (level - 1) * 2
max_hp = base_hp + (level - 1) * 2
```

Атака героев не растёт.

### Механики героев

У героев усиливаются только:

- `reflect_X`
- `armor_X`
- `aura_atk_X`
- `start_mana_X`
- `regen_X`

Формула:

```text
X + floor((level - 1) / 3)
```

Для `start_mana_X` есть ограничение `min(10, value)`.

Текущие герои:

| Герой | База | L4 | L7 | L10 |
|---|---|---|---|---|
| Искатель | 35 HP, без механик | 41 HP | 47 HP | 53 HP |
| Жанна д'Арк | 35 HP, `aura_atk_1` | 41 HP, `aura_atk_2` | 47 HP, `aura_atk_3` | 53 HP, `aura_atk_4` |
| Аскеладд | 40 HP, `reflect_1` | 46 HP, `reflect_2` | 52 HP, `reflect_3` | 58 HP, `reflect_4` |
| Даркнесс | 45 HP, `armor_1` | 51 HP, `armor_2` | 57 HP, `armor_3` | 63 HP, `armor_4` |
| Росомаха | 37 HP, `regen_1` | 43 HP, `regen_2` | 49 HP, `regen_3` | 55 HP, `regen_4` |
| Олег Тиньков | 23 HP, `start_mana_1` | 29 HP, `start_mana_2` | 35 HP, `start_mana_3` | 41 HP, `start_mana_4` |

## Проблемные области

### Заморозка

Заморозка имеет бинарную механику `freeze`.

Фактический результат:

- L1-L10: всегда `freeze`
- длительность не увеличивается;
- число целей не увеличивается;
- стоимость маны не меняется;
- героя замораживать нельзя.

Если дизайн ожидает прогрессию, нужно явно выбрать модель: снижение маны, превращение в `aoe_freeze`, увеличение числа целей или новая параметрическая механика вроде `freeze_count_X`.

### Кража Маны

Кража Маны имеет `mana_drain_2`, но potion-scaling не усиливает `mana_drain_X`.

Фактический результат:

- L1-L10: всегда `mana_drain_2`, 3 маны

Если дизайн ожидает рост контроля маны, нужно добавить правило для `mana_drain_X` или альтернативно снижать стоимость маны.

## Технические точки интеграции

- `core/card_scaling.py` — расчёт статов и масштабирование механик.
- `core/converter.py` — нормализация механик и применение уровня при создании карты.
- `battle_engine.py` — загрузка уровней пользователя и режимы `normal`, `disabled`, `max`.
- `core/effects.py` — исполнение уже масштабированных механик.
- `core/engine.py` — боевой цикл, start-mana героев, ауры, регенерация, cleave, deathrattle.

## Расхождения с прежней документацией

Старая документация описывала линейный рост воинов через `floor(level / 2)` и более агрессивный рост урона зелий через `+level - 1`. Это больше не соответствует текущему коду.

Актуальная модель:

- воины: экспоненциальные статы по редкости;
- механики воинов: в основном `+1` каждые 2 или 3 уровня;
- зелья: обычный `damage_X` получает `+1` каждые 3 уровня;
- герои: `+2 HP` за уровень и `+1` к части пассивных механик каждые 3 уровня.
